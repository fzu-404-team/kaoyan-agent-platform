按键设计提案：妙控键帽

状态：待审批 日期：2026-11-19 适用：考研 Agent 平台前端（kaoyan-frontend） 依赖：答题纸视觉方向（登录页已采用）

把平台的按键做成苹果妙控键盘的键帽：每个按键有 2px 键程和底座阴影，按下时真的沉下去；常用快捷键直接印在按键上。刷题本来就靠键盘作答，这套按键让快捷键看得见。

本页的实样都可以操作：鼠标悬停、按下、用 Tab 键切换焦点，感受键程和反馈。键帽放进完整界面后的效果见同目录的 全量原型（覆盖平台全部页面，可在地址后加 ?state=session 等直接打开某个画面）；早先的 核心流程原型 仍保留。

1. 为什么选这一套

  • 反馈最明确。按下时键帽下沉 2px、底座阴影收起，一眼能看出“已经按到了”。长时间刷题时，确认感比装饰更重要。
  • 和刷题方式一致。刷题页已支持 A–D、1–4 选择、Enter 提交。键符印在按键上，用户不用读说明就知道可以用键盘做题。
  • 沿用已采用的答题纸配色。主色仍是钢笔蓝 #2F4A7A，危险操作仍用批改红 #B23A2E，不新增颜色。

同轮对比过的另外两套：A「墨水分级」（苹果四级主次，最稳但记忆点弱）、B「纸上液态玻璃」（半透明胶囊，最大胆，但依赖背景纹理、低端设备上毛玻璃耗性能、长时间使用易分心）。

3. 可访问性与已知问题

  • 所有按键文字对比度均达到 WCAG AA（4.5 : 1 以上）；焦点环已从半透明改为实色。
  • 键程动画只有 60ms 的位移；系统开启“减少动态效果”时去掉过渡，状态直接切换。
  • 键符对读屏软件隐藏，避免读成“提交答案 回车”；快捷键说明仍保留在页面的文字提示中。
  • 次键的描边和底座与纸色对比只有约 1.5 : 1，低于非文字元素 3 : 1 的建议值。按键靠文字和阴影仍可辨认，但视力较弱时边界不够清楚。可选方案：把描边加深到约 #8F8676（达到 3 : 1，但会显得更重），或维持现状并接受这一点。

4. 落地范围与步骤

  1. 登录 / 注册页：替换主按钮样式，链接保持文字样式。只改 AuthLayout.vue，不影响其他页面。
  2. 刷题页：提交、翻题、选项 A–D 改为键帽；与刷题页答题纸改版一起进行。
  3. 全站按钮：通过 Element Plus 按钮的样式变量统一替换，不引入新的组件库；表格内的文字按钮、链接不做成键帽。

每一步都会在桌面 1440×900 与手机 390 宽下截图检查，并运行现有前端测试与生产构建。

5. 待决定事项

  • 是否采用键帽作为平台按键样式。
  • 方向键翻题：新增 ← / → 快捷键并保留键符，或去掉“上一题 / 下一题”上的键符。
  • 次键描边：加深到满足 3 : 1，或维持当前较轻的效果。
  • 推广范围：只用于登录与刷题页，或推广到全站按钮。
