# 择校候选分级扩充验证记录（2026-11-19）

契约见[目录记录分级纳入正式候选契约](../考研Agent平台搭建文档.md#目录记录分级纳入正式候选契约2026-11-19)。

## 背景与授权

- 问题：081200 学硕的正式候选只有 8 所审核院校，每次最多展示 5 所，用户反馈“总是那几所”。
- 2026-11-19 用户批准：不另行逐条核实，把合格目录记录和往年分数统计纳入正式候选。本次只在本机生效，公网部署须另行授权。

## 改动范围

| 端 | 文件 | 内容 |
| --- | --- | --- |
| Python | `retrieval.py` | `Document.evidence_level()`；合格目录记录可生成引用，加载语料时校验其来源域名 |
| Python | `tools/schools.py` | `evidenceLevel` 字段、待核提示、分数统计候选（`score_programs`、`school_regions`）、同校代表与展示顺序 |
| Python | `agents/school.py`、`workflows.py` | 正式／线索划分、分数统计不进入引用、只在全部为官方复核时请求模型解释 |
| 配置 | `config/reference-hosts.json` | 新增 79 个院校域名（16 → 95） |
| Java | `TaskServiceImpl.java` | 校验 `evidenceLevel` 取值；仅 `SCORE_HISTORY` 允许 `sourceIds` 为空 |
| 前端 | `RecommendationCandidateList.vue`、`types/api.ts` | 等级放在折叠的「项目说明」末行（用户要求低调展示）；“学习方式未知”“地区未登记”文案 |

## 实施中的设计调整

最初按“地区 → 意向 → 证据等级 → 未展示”排序入选。冒烟时发现：未填地区的情况下，8 所审核院校总会占满 5 个名额，候选和改动前一样。因此改为：证据等级只决定同校代表和展示顺序，不参与入选抽样，契约已同步。
